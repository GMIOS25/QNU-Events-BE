### 2.2. Phân tích giá trị biên (Boundary Value Analysis — BVA)

| Biến / Tham số & Ràng buộc trong Mã nguồn | Giá trị dưới biên | Giá trị tại biên | Giá trị trên biên | Kỳ vọng thực tế theo Code | Mã TC phủ |
|---|---|---|---|---|---|
| **BVA-01: Cửa sổ điểm danh `now` vs `[attendanceOpenAt, attendanceCloseAt]`**<br>(`AttendanceService`: `now.isBefore(open) \|\| now.isAfter(close)`; `EventService`: `!isBefore && !isAfter`) | `now = attendanceOpenAt - 1ns` | `now == attendanceOpenAt` và `now == attendanceCloseAt` | `now = attendanceCloseAt + 1ns` | • `open - 1ns` và `close + 1ns`: `attendanceOpen = false` → `409 ATTENDANCE_NOT_OPEN` (`counted = false` ở `POST`).<br>• Tại đúng `open` và `close`: `isBefore`/`isAfter` đều `false` → **Chấp nhận** (đoạn đóng `[open, close]`). | `TC-QR-03`, `TC-QR-09`, `TC-QR-WB-07`, `WB-10` |
| **BVA-02: Kẹp `validUntil` cuối cửa sổ điểm danh**<br>(`AttendanceService.getQrToken`: `epochEnd.isBefore(close) ? epochEnd : close`) | `epochEnd < attendanceCloseAt` | `epochEnd == attendanceCloseAt` | `epochEnd > attendanceCloseAt` (vd `now = close - 2s`) | • `epochEnd < close`: `validUntil = epochEnd`.<br>• `epochEnd >= close`: `validUntil` bị kẹp bằng `attendanceCloseAt` (không báo thời hạn vượt quá giờ đóng cửa sổ). | `TC-QR-26`, `TC-QR-WB-07` |
| **BVA-03: Biên `epoch` & Ân hạn Grace Period**<br>(`QrTokenService.verify`: `secondsIntoCurrentEpoch = now.getEpochSecond() - (currentEpoch * rotationSeconds) <= graceSeconds`)<br>*Với `rotation = 10s, grace = 3s`, token `epoch = 100` (`1000..1009s`), `currentEpoch = 101` (`1010s+`)* | `t = 999.999s` (`currentEpoch = 99`, tương lai `+1`);<br>`t = 1000s` (đầu `epoch 100`) | `t = 1010s` (`+0s`);<br>`t = 1012.999s` (`+2s`);<br>`t = 1013.000s..1013.999s` (`secondsIntoCurrentEpoch = 3 <= 3`) | `t = 1014.000s` (`secondsIntoCurrentEpoch = 4 > 3`);<br>`t = 1020s` (`epoch <= current - 2`) | • `t = 999.999s`: `QR_FROM_FUTURE`.<br>• `t = 1000..1013.999s`: **Hợp lệ (`epoch = 100`)**. *(White-box Finding: do dùng `getEpochSecond()` cắt phần lẻ giây và phép `<=`, mốc `3.0s..3.999s` vẫn hợp lệ, khác tài liệu Test Plan ghi `< 3.0s`)*.<br>• `t >= 1014.000s` & `epoch <= current - 2`: `QR_EXPIRED`.<br>• Với `grace = 0`: `t = 1010.999s` (`0 <= 0`) hợp lệ, `t = 1011.000s` (`1 > 0`) → `QR_EXPIRED`. | `TC-QR-11`, `TC-QR-12`, `TC-QR-16`, `TC-QR-26`, `TC-QR-WB-05` |
| **BVA-04: Biên Số lần thử sai (`MAX_COUNTED_ATTEMPTS = 3`)**<br>(`AttendanceService`: `failedAttempts >= 3`) | `failedAttempts = 0`, `1`, `2` | `failedAttempts = 3` (lần gửi thứ 4) | `failedAttempts = 4` (nếu có dữ liệu vượt ngưỡng) | • `0`, `1`, `2`: cho phép kiểm tra token QR (nếu sai `QR_*` trả `422` và `counted = true` tăng dần `1 → 2 → 3`; ở lần 3 nếu gửi đúng vẫn `200 ACCEPTED`).<br>• `>= 3`: chặn ngay `409 ATTEMPT_LIMIT_REACHED`, `counted = false` (kể cả token hợp lệ).<br>• Các lỗi `NOT_REGISTERED`, `ATTENDANCE_NOT_OPEN`, `ALREADY_CHECKED_IN` có `counted = false` không làm tăng bộ đếm. | `TC-QR-17`, `TC-QR-23`, `TC-QR-25`, `TC-QR-WB-10` |
